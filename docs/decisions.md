# Решения и причины

Эти решения связывают исходную цель пользователя с текущей структурой проекта. Фактический checkpoint хранится в [state.md](../state.md), сценарии — в [agent-routes.md](agent-routes.md), происхождение файлов — в [provenance.md](provenance.md). История событий сохранена в [документах 8 ноября](history/2026-11-08/state-original.md) и [9 ноября](history/2026-11-09/state-original.md).

## D01. Управление через официальный Colab MCP на компьютере пользователя

**Требование.** Управлять Google Colab через браузер пользователя и Remote Desktop Commander, установить Blender и выполнить тест именно на A100.

**Решение.** Использовать официальный `googlecolab/colab-mcp` как stdio server в отдельном локальном Python-окружении; frontend подключается из открытой вкладки Colab к loopback WebSocket. Браузерные действия выполняются через штатный Browser plugin.

**Следствие.** Клонирование репозитория в облачную среду не восстанавливает браузерный контекст MSI. Существующая установка и новый компьютер имеют отдельные [маршруты](agent-routes.md). Вычисления и `/content` принадлежат Colab runtime и имеют его обычный срок жизни.

## D02. Один долгоживущий ClientSession и файловая очередь

**Причина.** Управление ячейками должно сохранять один MCP-сеанс между локальными вызовами. Несколько конкурирующих сеансов и неясные повторы после timeout осложняют восстановление.

**Решение.** [mcp_bridge.py](../mcp_bridge.py) держит ClientSession, [mcp_call.py](../mcp_call.py) отправляет запросы с уникальными ID. OS lock ограничивает очередь одним владельцем, ответы сохраняются до архивирования запросов. Оба скрипта остаются в корне, от которого вычисляют default project directory.

**Следствие.** Обработка последовательная; `__shutdown__` ждёт активный RPC. Timeout клиента не отменяет исполнение. Прерванный claimed request получает неопределённый исход и не воспроизводится автоматически. Подробности — в [architecture.md](architecture.md).

## D03. Закреплённый upstream и три проверенные правки

**Решение.** Сохранить revision `b9ab3899e0f1fa493390b1fd6d54aa2e464ecdf1`, package 1.0.1, Python 3.13.18 и uv 0.13.7. Patch содержит ровно три смысловых изменения: bind `127.0.0.1`, `shield` только startup task и входящий WebSocket cap 16 MiB.

**Причина.** Правки отвечают наблюдавшимся проблемам Windows с разными ephemeral ports, отмене startup task после wait timeout и закрытию большого output кодом 1009. Изменения auth и Origin не требовались.

**Следствие.** Перед обновлением upstream сохранить фактический diff и отдельно проверить его применимость. Новый version pin — самостоятельное изменение; исторические проверки не доказывают работу произвольной новой версии.

## D04. Связь проверяется несколькими независимыми шагами

**Решение.** Проверять свежесть bridge, семантический bootstrap result, актуальные schemas, правильный notebook и реальное небольшое исполнение. Сохранение Drive проверять отдельным UI-действием.

**Причина.** Bridge мог показывать свежий heartbeat при отсутствии frontend. Bootstrap мог открыть пустой scratchpad. Внешнее `ok: true` может содержать внутренний отрицательный результат. Успешно исполненная ячейка ранее исчезала после reload до подтверждённого Save.

**Следствие.** Исторические PID, port, tool count и GPU не объявляются действующими. Для проверки MCP достаточно smoke; Blender и GPU для этой операции не требуются.

## D05. A100 проверяется по фактическим данным

**Решение.** Default ожидаемого GPU — A100. Несовпадение останавливает подготовку/рендер; отдельный L4-тест требует явного выбора L4 и собственного статуса. Успех подтверждается фактической GPU, устройствами Cycles, отключением CPU tracing, GPU UUID/PID, CSV и свежими файлами.

**Причина.** Первый штатно выданный ускоритель оказался L4. Этот тест был полезной проверкой GPU-рендера, но исходную цель A100 не выполнил. Последующий запуск через MCP действительно использовал A100-SXM4-80GB.

**Следствие.** Доказательства [A100](../evidence/a100/render_report.json) и [L4](../evidence/l4/) хранятся раздельно. CPU denoise и подготовка сцены учитываются отдельно от устройства трассировки. Время первого запуска CUDA не используется как установившийся benchmark.

## D06. Blender и сцена воспроизводятся из полного исходника

**Решение.** Закрепить Blender 4.5.15 LTS и SHA256 дистрибутива `0d2b8bb2efe97e6c8eb57de6b7322f8800e1984e3125b60decca5f6771e4773e`. Передавать полный установщик, скрипт сцены и самостоятельный чистый notebook.

**Причина.** Ранний standalone installer выбирал актуальный патч ветки 4.5; для воспроизводимости в итоговый исходный пакет вошёл закреплённый установщик из notebook. Совпадение этого исходника с A100-архивом уже проверено.

**Следствие.** Данные исторической установки остаются provenance. Выполнение в новой VM требует собственной проверки GPU и отдельного output directory. Новый запуск описан в [render-and-export.md](render-and-export.md).

**Изменение при передаче в Git.** Чистый notebook в репозитории является производной версией исходного template. Изменены ячейки с индексами 2, 8, 11 и 12 при отсчёте с нуля. Конфигурация создаёт новый `OUTPUT_DIR` внутри `WORK_DIR/runs/` в каталоге по времени UTC с микросекундами и дочернем `output/`. Запуск отказывается перезаписывать непустой каталог. Пояснение экспорта и exporter используют именно этот `OUTPUT_DIR`, сохраняя прежние ZIP arcnames `output/*`. Прежний exporter жёстко читал `WORK_DIR/output` и после смены output directory мог захватить старый результат. Metadata чистого notebook также обновлены для A100. Встроенные полные исходники установщика и сцены сохраняются побайтно. Фактический рабочий UI-экспорт остаётся неизменённым; старые hashes и проверка совпадения 14 ячеек относятся к исходному template из полного пакета, а не к производному notebook репозитория.

## D07. Сохранённые результаты восстанавливаются до повторного рендера

**Решение.** После export timeout сначала проверить существующие outputs и файлы. 9 ноября исходный ZIP извлечён из output реально скачанного исторического notebook без исполнения его ячеек.

**Причина.** Вызов экспорта достиг 600 секунд, но JSON с base64 и архивом сохранился в ячейке 7 с ID `60JyQaCoFYp6`. Повторный рендер не требовался для получения уже созданного результата.

**Следствие.** Проверены SHA архива, CRC, безопасные пути, все 12 manifest entries, report и телеметрия. `A100_run_summary.json` остаётся сводкой stdout, а полный report — отдельным исходным файлом. Скрипт [recover_a100_from_notebook.py](../scripts/recovery/recover_a100_from_notebook.py) сохраняется как инструмент восстановления конкретного исторического формата.

## D08. Лёгкий рабочий notebook отделён от тяжёлого исторического

**Решение.** Работать в сохранённом notebook `Blender_Colab_A100_Working_2026-11-09.ipynb`: 14 чистых исходных ячеек и одна recovery smoke-ячейка. Исторический документ с base64-экспортом сохраняет роль источника доказательств.

**Причина.** Историческая вкладка зависала после reload. Причина не установлена; большой output — гипотеза. Создание лёгкой копии позволило восстановить управление и проверить Save без нового GPU-рендера.

**Следствие.** Последний smoke относится к стандартной CPU VM: `gpu_probe: null`, `blender_present: false`, `render_executed: false`. Это не состояние исторического A100-прогона. Промежуточный checkpoint 14 ячеек с `requires_drive_save: true` предшествует финальному сохранённому checkpoint 15 ячеек.

## D09. Один владелец живой среды, параллельный анализ копий

**Решение.** Ведущий агент единолично меняет notebook, runtime и живую очередь. Проверяющим агентам назначаются чтение копий, независимая проверка артефактов и непересекающиеся документы.

**Причина.** Конкурирующие действия могут сменить document identity, повторить RPC, перезаписать output или нарушить привязку browser/bridge.

**Следствие.** Перед параллельной работой назначаются владельцы файлов и действий. Состояние проекта обновляется после рабочей волны. Публикация и ревью документов не требуют нового MCP-сеанса или GPU-теста.

## D10. Основной результат доступен из Git, полный исходный пакет имеет отдельную provenance

**Решение.** В репозиторий входят код, актуальные инструкции, чистый и рабочий notebooks, компактные доказательства, [preview PNG](../assets/test_render_A100.png) и [исходный A100 ZIP](../artifacts/a100/Blender_Colab_A100_Render_2026-11-08.zip). Этот ZIP содержит `.blend`, PNG, report, CSV, логи и исходники проверенного прогона.

**Причина.** Следующему агенту нужен самостоятельный доступ к основному результату через GitHub. Повторяющиеся крупные бинарные файлы, тяжёлый executed notebook и длинные сырые snapshots уже сохранены в полном пакете владельца.

**Следствие.** Основной A100-комплект восстанавливается без доступа к частному полному пакету. Полный архив 14 288 213 байт с SHA256 `ba3389693a98b4b6158f45a63d7e32e2ac74c12c6ccca86a5f971e866eecf021` остаётся источником полного исторического снимка. Его ссылка, состав и ограничения доступа описаны в [provenance.md](provenance.md). В Git исторические Markdown переименованы в `*-original.md`, чтобы прежний `AGENTS.md` не действовал как вложенная инструкция. Эти копии получили предупреждение об историческом статусе и исправленные относительные ссылки; ссылки на недоступные файлы переведены в обычные названия. Содержательные абзацы сохранены. Побайтные оригиналы находятся в полном исходном архиве, а исходные SHA и преобразования фиксируются в provenance.

## D11. Происхождение и секреты сохраняют разные правила

**Решение.** Оставить нужные notebook URLs, имена файлов, целевые project paths, timestamps, request IDs и hashes. Исключить auth fragments, токены, cookies, OAuth credentials, сырые приватные bridge logs, `bridge_state`, vendor и `.venv`.

**Причина.** Пути и идентификаторы связывают доказательства с проектом. Авторизационные данные дают доступ и не нужны для воспроизводимости опубликованного результата.

**Следствие.** Notebook URL остаётся указателем на документ и подчиняется доступу Google Drive. Новый агент использует свой разрешённый браузерный контекст. Исходные hashes относятся к конкретным исходным байтам; изменённый metadata notebook или перерасположенный комплект получает собственные проверки и не выдаётся за неизменённый исходный архив.

## Нерешённые технические вопросы

- Точная причина зависания тяжёлой вкладки не установлена.
- Причина неподтверждённого автосохранения первой smoke-ячейки не установлена.
- Local Network Access не доказан как причина раннего сетевого сбоя.
- Следующая живая сессия, её PID/port, GPU и наличие Blender требуют новой проверки по текущему заданию.

Эти вопросы не препятствуют чтению проекта, проверке сохранённого A100-комплекта и подготовке следующей задачи. Гипотезы не превращаются в конфигурационные требования без новых наблюдений.
