## Маршруты и роли

**Ведущий агент** управляет Browser, Colab runtime и очередью MCP. Только один агент одновременно меняет notebook или управляет средой.

**Агент проверки** может независимо анализировать локальные копии, проверять ZIP/manifest/report/CSV и обновлять выделенные документы или каталог упаковки. Параллельное изменение той же вкладки, runtime или исходных файлов не допускается без явного распределения владельцев.

**Восстановление подключения:**

1. Проверить уже работающий bridge; не запускать второй экземпляр.
2. Если доступен только bootstrap, восстановить штатное подключение Browser и `open_colab_browser_connection`.
3. Bootstrap может открыть пустой scratchpad, который виден только среди пользовательских вкладок. Прежде чем добавлять код, сверить URL и содержимое через `get_cells`.
4. Для перепривязки использовать актуальные данные текущего bridge и штатный Connect. Auth fragment не сохранять и не выводить.
5. После появления 8 инструментов проверить правильный notebook. При восстановлении связи достаточно небольшой smoke-ячейки; запуск Blender не требуется.
6. После изменений выполнить **Файл → Сохранить**, дождаться **«Изменения сохранены»**, затем проверить итоговое чтение. Успех RPC не подтверждает Drive save.

**Новый рендер по новой задаче:**

1. Согласованный новый объём работы определяет сцену и параметры.
2. Выбрать A100 и проверить фактическую GPU до загрузки Blender.
3. Использовать закреплённый установщик и A100 guard. Для отдельно обозначенного L4-теста требуется явный `EXPECTED_GPU = "L4"`; не подменять им A100-цель.
4. Сохранять результат в отдельный каталог, не перезаписывая текущий контрольный A100-комплект.
5. Выгрузить PNG, `.blend`, исходный report, CSV и логи вне VM; проверить manifest и обновить `state.md`.
