## Достоверность результата

- Различать выбранный accelerator в UI, реально выданный GPU, устройство Cycles и подтверждённый процесс на GPU.
- Сохранять историю первого L4 прогона отдельно; его GPU, канал выполнения через notebook UI и `target_a100_met: false` не переносить на итоговый A100 результат.
- Успех MCP подтверждать инструментами ячеек после bootstrap и фактическим исполнением кода через MCP.
- Проверять привязку: пустой bootstrap-scratchpad и рабочий notebook — разные документы. До записи сверять URL и `get_cells`.
- Различать успешный рендер и полную выгрузку. Рендер подтверждён сохранённым MCP-ответом, `GPU_RENDER_SUCCESS` и PNG. Для полной передачи ещё проверить оригинальные `.blend`, JSON-отчёт и CSV после копирования. Сводка, извлечённая из stdout, не является исходным полным `render_report.json`.
- Время итогового A100 рендера 490.448 с включает примерно 483 с до `Sample 0/96` при первом запуске CUDA kernels. Не трактовать это как установившуюся скорость трассировки и не сравнивать напрямую с 7.961 с первого L4 отчёта.
- CPU может выполнять подготовку сцены и OpenImageDenoise. В проверенном тесте CPU-устройство Cycles для трассировки отключено.
- Сохранять GPU guard. Для отдельно обозначенного L4 теста использовать явный `--expected-gpu L4`; основной default — A100.

## Порядок работы и маршруты

Ведущий агент управляет браузером и ПК через разрешённые инструменты. Другим агентам можно поручать исследование официальной документации, подготовку сцены и ревью, но не параллельное изменение той же вкладки или runtime.

1. Восстановить штатный Browser plugin через эту беседу в браузере с подключённым расширением. Не обходить требование исходного контекста альтернативным транспортом. Проверить уже существующий runtime, сохраняя результаты в нём.
2. Если MCP потерян, восстановить bridge, выполнить `__list_tools__`, штатный bootstrap и снова `__list_tools__`; использовать реальные схемы инструментов.
3. Проверить привязку через `get_cells`, затем выполнить небольшую smoke-ячейку, если подключение было восстановлено или изменилось.
4. После изменений ячеек через MCP выполнить **Файл → Сохранить** и дождаться **«Изменения сохранены»** перед reload или сменой runtime. Успех RPC не доказывает сохранение notebook на Drive. Причина неподтверждённого автосохранения в первой попытке не установлена.
5. В текущем checkpoint не менять VM: завершить копирование существующих A100 результатов. Если позднее runtime действительно утрачен, зафиксировать потерю неподтверждённых копий; новый рендер не запускать автоматически. Для отдельного будущего запуска использовать закреплённый notebook.
6. Проверить существующий экспортный архив: таймаут RPC не доказывает его отсутствие, но наличие в Colab не доказывает скачивание. Подтвердить копию вне runtime, проверить ZIP и файлы, обновить `state.md`. Этот компактный checkpoint включает только полученные материалы. Следующий маршрут: Browser context → штатный MCP → identity/get_cells → обычное скачивание существующего архива → сохранение чистого notebook в Drive. Полный финальный пакет собирать после проверки оригиналов.

Если MCP временно потерян, полезную работу допустимо выполнять через notebook UI, честно фиксируя канал выполнения. Не менять тариф и не покупать ресурсы автоматически. Не занимать новую GPU-сессию для повторной проверки уже завершённого рендера.

Bootstrap-scratchpad может появиться среди внешних пользовательских вкладок: в этой сессии его обнаружил `browser.user.openTabs`, хотя `browser.tabs.list` его не показывал. Для перепривязки использовались актуальный URL fragment bootstrap-вкладки, закрытие только созданного scratchpad, добавление fragment к рабочему notebook, reload и штатный Connect. После этого `get_cells` подтвердил рабочий документ. Fragment не сохранять и не публиковать.

## Ограничения доступа и секреты

- Browser tool отклонил служебный протокол `chrome://settings`. Не обходить отказ через другой транспорт, CDP, shell, файлы профиля или registry. Ручная проверка разрешения пользователем описана в README.
- Историческое MCP-подключение после сообщения пользователя «готово» было успешным. LNA не установлена как точная причина прежнего сбоя. Нынешний отказ Browser plugin связан с требованием исходного контекста по тексту ошибки; не приписывать его LNA и не отключать token/Origin-проверки.
- Не извлекать cookies, OAuth-токены или браузерные credentials. Не помещать MCP token, авторизационные URL, сырые приватные логи или `bridge_state` в передаваемый архив.
- Сохранять token/Origin-проверки. Bind только loopback. WebSocket-лимит оставлять конечным: 16 MiB в проверенной конфигурации.
- Не использовать anti-idle или повторные выдачи runtime для обхода квот Colab.

## Окружение и жизненный цикл

Для MCP использовать явный Python 3.13.18 из `vendor\colab-mcp\.venv`; системный Python 3.10 для него не подходит. Upstream revision `b9ab3899e0f1fa493390b1fd6d54aa2e464ecdf1`, package 1.0.1. Три локальные правки: host `127.0.0.1`, `shield` только startup task, `max_size=16 * 1024 * 1024` для входящего WebSocket-сообщения. Перед обновлением vendor сохранить и проверить фактический diff.

Bridge обрабатывает файловую очередь последовательно; предел вызова — 600 секунд. `--detach` отправляет запрос, `--result` читает его ответ. Истечение ожидания CLI не даёт основания повторять изменяющий инструмент: код может продолжать выполняться в Colab. После аварии запрос в `processing` может уже иметь эффект; сначала проверить Colab, автоматический replay запрещён.

Останавливать свободный bridge через `__shutdown__`. Этот запрос не прерывает текущий RPC. При аварийном завершении сначала проверить текущий executable, command line и принадлежность процесса; исторические PID не использовать. Не завершать чужие Blender, браузерные или Colab задачи.

После рабочей волны обновлять `state.md`: подтверждённый результат, источник доказательства, оставшиеся действия и точный следующий шаг. Компактный checkpoint содержит только реально полученные файлы и явно описывает недостающие. В полном пакете после выгрузки основной `output/` должен быть A100, история L4 — отдельно в `previous_l4/`. Пересчитать `SHA256SUMS.txt` после окончательного состава; не включать vendor, `.venv`, `__pycache__`, tokens или `bridge_state`.

В `Blender_A100_Checkpoint_2026-11-08.zip` файл `install_blender.py` — закреплённый исходник из чистого notebook, а не прежний standalone installer с выбором актуального патча. Старый полный ZIP и исторические L4 артефакты в checkpoint не включены.
