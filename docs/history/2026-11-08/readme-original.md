## Разрешение Chrome при повторном подключении

Ранее проверялась гипотеза о разрешении Local Network Access / Loopback network. В первой части сессии после сообщения пользователя «готово» о ручной проверке и нового штатного подключения MCP заработал. **Точная сетевая причина прежнего сбоя не установлена:** одной временной последовательности недостаточно, чтобы приписать сбой разрешению Chrome. Инструмент браузера отклонил доступ к служебным `chrome://settings`; обходы не применялись.

Исторический успех не подтверждает нынешнее соединение. При текущем blocker исходного браузерного контекста повторять проверку LNA без новой сетевой ошибки не требуется. Если появится новая ошибка доступа, после сохранения результата рендера пользователь может проверить разрешение вручную:

1. В той же вкладке Colab нажать значок **«Сведения о сайте»** слева от адреса.
2. Открыть **«Настройки сайта»** именно для `colab.research.google.com`.
3. Найти **«Доступ к локальной сети»**. Если пункты разделены, нужен **Loopback network**, то есть доступ к сервисам на этом компьютере.
4. Выбрать **«Разрешить» / Allow** для этого сайта.
5. Вернуться в Colab, обновить вкладку и повторить Connect с текущим MCP-процессом. Если появится запрос Chrome к локальным приложениям/сервисам — подтвердить его для Colab.
6. Если пункта нет или он управляется политикой, сохранить скриншот и продолжить диагностику без отключения защиты.

Не требуется сброс всех разрешений, удаление cookies, изменение «Небезопасного контента» или отключение защитных флагов. Официальные источники: [русская справка Chrome](https://support.google.com/chrome/answer/114662?co=GENIE.Platform%3DDesktop&hl=ru), [LNA и loopback](https://developer.chrome.com/docs/modern-web-guidance/guides/security/local-network-access), [WebSocket LNA в Chrome 147](https://developer.chrome.com/release-notes/147).

## Сохранение и завершение

Сохранённый notebook не делает `/content` постоянным хранилищем. При завершении или замене runtime Blender, сцены и результаты могут исчезнуть. После каждого значимого рендера сохранить PNG, `.blend`, отчёт и телеметрию вне runtime и обновить `state.md`. После смены VM установить Blender заново из закреплённого notebook и проверить фактический GPU до рендера. Не удалять runtime до проверки копии. Управление временем жизни, доступность A100 и баланс вычислительных единиц остаются ограничениями Colab; не имитировать активность ради обхода этих ограничений. См. [официальный FAQ Colab](https://research.google.com/colaboratory/faq.html).
