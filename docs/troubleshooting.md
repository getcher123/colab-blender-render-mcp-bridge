# Диагностика подключения и результатов

Начать с [state.md](../state.md) и выбрать маршрут в [agent-routes.md](agent-routes.md). Таблица ниже относится к фактически наблюдавшимся сбоям и поведению [bridge](../mcp_bridge.py). Последний сохранённый успешный checkpoint не подтверждает соединение в момент нового обращения.

## Симптом → проверка → действие

| Симптом | Что проверить | Следующее действие |
| --- | --- | --- |
| `bridge_not_started` или `server_executable_missing` | Правильность project directory и наличие `vendor/colab-mcp/.venv` | На новом компьютере пройти [setup-windows.md](setup-windows.md); существующую установку проверить до повторной установки |
| `bridge_not_ready_or_heartbeat_stale` | `state`, `heartbeat_age_seconds`, executable и command line процесса | Определить состояние текущего bridge; запускать новый после подтверждения отсутствия работающего владельца |
| `--status` завершился с кодом 0, но связь не работает | Поля JSON, а затем инструменты и notebook | Код 0 означает успешное чтение файла status; свежесть и подключение проверяются отдельно |
| `Another bridge owns this queue` | Какой процесс держит эту очередь; правильный ли `--project-dir` | Продолжить через существующий bridge либо штатно остановить свободного владельца |
| Доступен только `open_colab_browser_connection` | Подключён ли frontend к текущему процессу | Выполнить штатный bootstrap и [восстановление связи](recover-connection.md) |
| Bootstrap показывает внешнее `ok: true` | Вложенный `result.structuredContent.result`, затем текущие tools | При `false` подключение не подтверждено; продолжить диагностику frontend |
| После bootstrap `get_cells` пуст | URL документа и список пользовательских вкладок | Проверить setup scratchpad; перепривязать целевой notebook штатным Connect до записи кода |
| Вкладка отсутствует среди управляемых Browser tabs | Пользовательские открытые вкладки | В наблюдавшейся сессии scratchpad находился через `browser.user.openTabs` |
| Browser сообщает требование исходного контекста | В каком браузере открыта беседа и подключено расширение | Восстановить штатный Browser plugin в исходном контексте; продолжить доступную локальную работу |
| `client_wait_expired` | Сохранённый request ID, `active_request`, наличие outbox | Читать существующий ответ через `--result`; автоматический повтор изменяющего действия не выполнять |
| `TimeoutError` или `execution_uncertain: true` | Ответ по ID, содержимое notebook и фактический эффект | Зафиксировать определённые результаты; новый запрос отправлять после выяснения эффекта старого |
| `request_id_already_used` или `request_id_reserved` | Относится ли ID к нужному уже отправленному действию | Получить существующий результат; для действительно новой операции использовать новый ID |
| `get_cells` с большим output закрывает WebSocket с 1009 | Применён ли patch 16 MiB; размер outputs | Проверить текущий diff; использовать компактное чтение и отдельно экспортировать крупные файлы |
| Ячейки исчезли после reload | Было ли явное сохранение подтверждено UI | Сверить outbox, восстановить только необходимые изменения и явно сохранить notebook |
| Историческая вкладка зависает после reload | Есть ли уже проверенный экспорт результатов | Продолжить из лёгкого рабочего notebook; сохранённый A100-комплект доступен отдельно |
| Smoke показывает `gpu_probe: null`, `blender_present: false` | Какая VM выделена текущему notebook | Это ожидаемые данные CPU-smoke восстановления; GPU нужен только для новой задачи рендера |
| GPU guard остановил установку или рендер | Фактически выданный GPU, `EXPECTED_GPU` и цель пользователя | Для A100 дождаться штатной выдачи A100; отдельно согласованный L4-тест явно пометить L4 |
| `__shutdown__` ещё не обработан | Есть ли активный RPC и другие запросы | Дождаться последовательного выполнения; shutdown не прерывает текущую операцию |

## Безопасная проверка уже отправленного запроса

`mcp_call.py --result` принимает фактический ID сохранённого запроса и не создаёт новый RPC. Для исторической диагностики предпочтительно читать соответствующий файл из `evidence/`; исторические ID не отправляются повторно в рабочую очередь.

Если CLI завершился по своему таймауту, запрос может оставаться в `inbox/`, исполняться в `processing/` или уже иметь результат в `outbox/`. Если bridge завершился после claim, при следующем старте он помечает такой запрос как неопределённый и архивирует его без replay. Это сохраняет различие между неизвестным исходом и доказанной неудачей.

Обрыв transport или истечение 600 секунд ожидания RPC не доказывает, что Colab прекратил исполнение. Именно после export timeout исходный A100 ZIP был восстановлен из сохранённого output notebook. Перед повтором экспорта или ячейки сначала проверить уже существующие outputs и файлы.

## Bootstrap и привязка к правильному документу

Штатный bootstrap может открыть новый пустой scratchpad. До добавления ячеек ведущий агент сверяет URL и `get_cells` с рабочим документом из [state.md](../state.md). Исторически scratchpad был виден только среди пользовательских вкладок, поэтому отсутствие в управляемом списке не означало отказа запуска.

При перепривязке используются актуальные данные текущего bridge и штатный Connect. Авторизационный fragment держится только в текущем разрешённом браузерном действии. Его не переносят в репозиторий, историю чата, скриншоты для публикации или логи передачи. Закрывать можно только scratchpad, созданный и опознанный в этой попытке; чужие вкладки и runtime не затрагиваются.

После подключения нужны свежий список инструментов, идентичность документа и короткая smoke-ячейка. Рендер Blender для диагностики управления не требуется. После любых изменений ячеек выполнить **Файл → Сохранить**, дождаться **«Изменения сохранены»** и проверить итоговое чтение.

## Границы диагностики

Сначала выполняются доступные чтение состояния и анализ локальных доказательств. Изменения вкладки, runtime, bridge и очереди выполняет один назначенный ведущий агент. Результат прошлой операции сохраняется до перезапуска или смены VM.

Проверки token и Origin, loopback bind и конечный WebSocket cap сохраняются. Сырые приватные bridge logs могут содержать данные доступа; для ревью выбираются только нужные поля без секретов. Тариф, покупки ресурсов, anti-idle и обходы квот не относятся к восстановлению этого проекта.
