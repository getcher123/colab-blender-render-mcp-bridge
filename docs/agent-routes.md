## Общие развилки

**Локальный код доступен, MSI недоступен.** Анализ, проверка архивов и работа с документацией возможны без live Colab. Для live-задачи нужен доступ к машине, на которой одновременно находятся браузер Colab и loopback MCP server. Облачный clone и GitHub permissions не дают такой доступ. Указать конкретный отсутствующий канал доступа; не объявлять соединение восстановленным по старому evidence.

**В очереди есть запрос.** Сначала выяснить `active_request`, наличие `inbox`/`processing`/`outbox` и реальный эффект в notebook. Возврат к новой операции возможен после установления результата или явного решения, как поступить с неопределённым исходом. Перезапуск процесса не служит способом повторить операцию.

**Видно 8 tools, но notebook чужой.** Вернуться к binding в recovery. Число инструментов подтверждает frontend, а не идентичность документа.

**Виден CPU runtime.** Это допустимо для восстановления MCP и соответствует последнему checkpoint. При новой задаче A100 требуется отдельный выбор и проверка фактического GPU через render route. Исторический `target_a100_met: true` не описывает новую VM.

**Нужны исходные файлы A100.** Они уже находятся в ZIP этого репозитория. Зависшую историческую вкладку или новый render для их получения запускать не требуется.

## Роли и контроль перехода

Ведущий владеет live notebook, runtime и изменяющей очередью. Проверяющие получают локальные копии и отдельные файлы. Завершение сценария отмечается конкретными evidence/временем UTC; «команда вернула 0» без проверки семантики недостаточно.

После значимых действий обновить [state.md](../state.md) и выполнить [handoff](handoff.md). Для файловой задачи без обращения к Colab явно сохранить прежнюю отметку времени live checkpoint. Не переписывать её временем коммита.
